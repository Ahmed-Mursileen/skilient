### 5.18 Verified CV

- **Principles:** generated from verified data only, never written by the student; every item traceable to evidence; checkable by anyone via QR code or PDF upload.
- **ATS format (required):** single column, standard headings (Summary, Skills, Projects, Open-source work, Endorsements, Credentials, Education), real selectable text, no tables or images carrying content, Spectral and Barlow with standard fallbacks. The QR code and verify link sit in the footer so they don't disturb parsing. Recruiters can drop it into any applicant-tracking system unchanged.
- **Content:** header (name, verified university, programme, batch, tier and percentile, QR code); a template-generated summary (no AI text); skills at L2+ only, up to 15, with level and evidence counts; completed and in-progress ventures with role, dates, team size, peer-verified contribution summary (faculty-confirmed entries marked), a "Reviewed by faculty" badge where reviewed, skills and links (team-written descriptions labelled and frozen in the snapshot); merged external PRs; up to 5 endorsements tied to evidence; admin-verified credentials; education. No CGPA, no free text, no L0 or L1 skills. Private repos appear as "Private repository". The student's "looking for" line lives on the profile, not the CV.
- **Refresh:** Free CVs regenerate on the 1st of each month with that month's new contributions, projects and ventures; Pro students regenerate anytime.
- **Formats and access:** live web CV at `/cv/[username]` (private, share-link, recruiters-on-Skilient or public); share links need **Spark tier** (7/30/90-day or no expiry, revocable); **ATS PDF export is a Student Pro feature** (or university-sponsored); signed JSON for the recruiter API.
- **Contact:** a Skilient contact link by default; showing an email is opt-in.
- **Signing:** each snapshot is canonical JSON (RFC 8785), SHA-256 hashed and signed with an Ed25519 key (key id recorded, yearly rotation, public keys at `/.well-known/skilient-cv-keys.json`). A random 10-character code links to `/verify/[code]`; the PDF file hash is stored too.
- **Verify page statuses:** Valid, Superseded (newer CV exists), Outdated (over 12 months), Revoked, Altered (uploaded PDF doesn't match), Not found. Rate-limited to 30 lookups per minute per IP.
- **Control:** revoke any version or link anytime; account deletion or suspension revokes all. Pro students see which companies viewed their CV; free students see counts.
- **Generation:** server action builds the snapshot as the owner; HTML template rendered to PDF by headless Chromium in a Vercel Node function; p95 under 10 s; PDFs in a private `cv-exports` bucket via short-lived signed URLs.

#### Build: verified CV

- **Files:** `lib/cv/snapshot.ts` (build snapshot JSON from the database as the owner), `lib/cv/canonical.ts` (RFC 8785 canonicalisation), `lib/cv/sign.ts` (Ed25519 via `@noble/ed25519`; private key fetched from Vault by a server-only helper), `lib/cv/templates/*.tsx` (ATS templates: one free, four Pro), `app/api/cv/pdf/route.ts` (Node runtime, `@sparticuz/chromium` + `puppeteer-core`), `app/cv/[username]/page.tsx`, `app/verify/[code]/page.tsx`, `app/me/cv/page.tsx`, `app/.well-known/skilient-cv-keys.json/route.ts`.
- **Snapshot build:** reads profile, `user_skills` (level ≥ 2, top 15 by level then evidence), completed and in-progress ventures with contributions and deliverables, external PRs, up to 5 visible endorsements, verified credentials, tier and percentile; applies `cv_settings` (sections on/off, order); outputs a typed `CvSnapshotV1`.
- **Monthly refresh:** `cv-refresh` job at 00:30 on the 1st builds a new snapshot for every Spark+ student whose data changed since the last one (hash compare), marks the previous version superseded, and leaves no PDF (PDFs exist only for Pro exports).
- **On-demand refresh (Pro):** `refreshCv()` requires `cv.refresh_on_demand`; limited to 10 per day.
- **Issue:** `issueCv()` → canonical JSON → SHA-256 → Ed25519 signature → random 10-char base32 code (retry on collision) → `cv_records` insert.
- **PDF export (Pro):** `exportCvPdf(recordId, template)` requires `cv.pdf_export`; the route renders the template HTML with the snapshot, prints A4 or Letter with embedded fonts, embeds the code and QR (`qrcode` package, SVG), stores it in `cv-exports/{user_id}/{record_id}.pdf`, saves `pdf_hash`, and returns a 60 s signed URL.
- **ATS check:** every template has a CI test that extracts text with `pdf-parse` and asserts section headings, order and that all skills and project titles are present as text.
- **Verify page:** server-rendered; looks up `code`, re-checks the signature with the public key for `key_id`, and determines the status. The PDF upload hashes the file in the browser (Web Crypto) and sends only the hash. Rate limited to 30 lookups per minute per IP, counted in `rate_limit_events`.
- **Share links:** `createShareLink(expiresIn)` requires Spark tier; token 32 random bytes; `/cv/[username]?t=` validates it server-side and logs `cv_views`.
- **Done when:** tampering one byte of a PDF shows Altered; a revoked record shows Revoked; every template passes the ATS text test; keys rotate without breaking old CVs.
